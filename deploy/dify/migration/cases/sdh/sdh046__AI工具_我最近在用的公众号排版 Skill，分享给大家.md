# 我最近在用的公众号排版 Skill，分享给大家

我这段时间写公众号，基本把“排版”这件事交给 AI 了。

它不是一个在线编辑器，也不是帮我代写文章的工具，而是一套安装在 Codex、WorkBuddy、Claude Code 这类 Agent 里的公众号排版 Skill：我把写好的文章交给它，指定一个主题，它会生成能直接进公众号编辑器的富文本 HTML。

## 1. 为什么我开始用它？

以前写完文章，最消耗耐心的往往不是内容，而是后面的排版：标题层级、重点标记、引用块、图片、结尾 CTA，调半天；粘进公众号后还可能掉样式。

我需要的不是花哨，而是三件事：

- 内容写完后，能快速得到一版干净、有阅读层级的公众号排版；
- 同一类文章保持统一风格，而不是每次从头设计；
- 排完能校验，避免粘贴后整篇样式乱掉。

这个 Skill 刚好解决了这三件事。现在我把精力放在选题、标题、案例和转化链路上，排版交给它做最后一公里。

## 2. 它到底能做什么？

它会把 Markdown、Word、PDF 或纯文本整理成公众号可用的 HTML，并自动处理：

- 章节编号、标题层级、目录与引言卡；
- 正文关键词强调、引用、列表、表格、代码块和图片；
- 作者签名和文末互动区；
- 公众号的兼容性校验，重点避免“复制进去样式掉了”。

它目前有多套主题。比如我常用的：

- **摸鱼绿**：教程、清单、工具盘点、信息密度高的内容；
- **紫蓝商业风**：商业复盘、社群运营、增长案例、项目总结；
- **石墨极简风**：专业观点、科技/设计评论；
- **橄榄手记**：案例复盘、内刊式深度内容。

我不会随机选。文章是什么类型，就用对应气质的主题。

## 3. 我是怎么用的？

### 第一步：安装

把下面这句话直接发给你的 Agent：

> 帮我安装这个公众号排版 Skill：`https://github.com/isjiamu/gzh-design-skill`

安装成功后，后续不需要每次再配环境。

### 第二步：把文章交给它

最简单的说法是：

> 用“摸鱼绿”把这篇文章排成公众号格式，生成预览页。

你可以直接粘贴文字、给一个 Markdown 文件，或者把飞书文档链接发给它。主题明确时直接指定；没想好时，让它根据文章类型推荐即可。

### 第三步：先看预览，再进公众号

它会产出两份东西：

1. 干净的公众号正文 HTML，作为兜底；
2. 带“复制到公众号”按钮的预览页。

我通常打开预览页，确认标题、图片和重点没问题，点复制，再粘到公众号编辑器。

### 第四步：需要时直接进草稿箱

如果你的公众号接口已经配置好，我现在的流程还可以继续做：上传正文图片、生成封面、创建公众号草稿。

注意：这一步是**保存到草稿箱**，不是自动发布。最后仍然建议自己在后台检查一遍再发。

## 4. 它带来的实际效果

对我来说，最大的效果不是“文章变好看了”，而是内容生产更稳定了：

- 同一账号的视觉风格统一，读者更容易形成识别；
- 长文章有清楚的阅读路径，重点不会埋在大段文字里；
- 以前要反复手调的格式，现在可以复用；
- 每次都会跑兼容性校验，降低公众号粘贴翻车概率；
- 我可以把更多注意力放回内容本身：这篇是拉新、建信任，还是承接咨询/社群。

## 5. 几个使用提醒

1. **它主要负责排版，不替代选题和内容判断。**先把文章的核心观点、读者对象和 CTA 想清楚，排版才能放大效果。
2. **一篇文章最好只用一套主题。**不要把不同风格的组件混在一起，容易显乱。
3. **图片进入草稿箱前要上传到公众号。**本地图片或临时链接不能直接留在正文里，否则草稿里可能失效。
4. **一定先看预览。**尤其检查标题是否过长、图片位置、重点是否准确、结尾 CTA 是否和文章主题相关。
5. **不要把“推草稿”理解成“自动发布”。**草稿创建后，还是要自己在公众号后台做最后检查和发布。

## 最后
